# Bearings 0.1.0 release candidate 1

Bearings connects recorded infrastructure and installed software to vulnerability evidence, responsible teams and remediation. This pilot release candidate brings together signed Windows client updates, the software coverage ledger and the current CVE and FlowIntel workflows.

## Implemented features

| Area | Capabilities and documentation |
| --- | --- |
| Inventory | Organization-scoped machines, software, emergency contacts and NetBox integration. The software ledger accounts for every recorded installation, shows why evaluation is incomplete and links to the underlying evidence. [Inventory overview](../user-guide/infrastructure-overview.md) · [Software coverage](../user-guide/software-coverage.md) |
| Inventory clients | Shared bounded rollout keys for Linux and Windows, authenticated periodic reports and per-device status. Windows has standalone x64, ARM64 and x86 executables, a setup window and scheduled reporting. Local uninstall and scoped deregistration are available for both platforms. [Linux rollout](../integrations/linux-rollout.md) · [Windows setup and lifecycle](../../clients/windows/README.md) |
| Windows client updates | An operator can publish signed releases for each architecture. Enrolled clients verify and activate the new release while keeping the enrollment and pending reports. Older clients require a one-time bootstrap update. [Signed client update operations](../operations/windows-client-updates.md) |
| Vulnerability review | Browse by CVE, machine or software. Filter by CVSS, Ubuntu priority and assessment. See current match, cleared version, stale evaluation and evidence gaps separately from human assessments. Vendor-listed package fixes include known update channels. [Continuous review](../user-guide/continuous-review.md) · [Linux vendor feeds](../integrations/distro-cves.md) · [Windows CVE coverage](../integrations/windows-cves.md) |
| Remediation | Prepare private FlowIntel plans by CVE or machine. Group vendor fixes, record reviewed mitigations, verify recipients and approve hand-off. Follow tasks and compare current version evidence after changes. [FlowIntel workflow](../user-guide/flowintel.md#plan-remediation-by-cve-or-machine) |
| Risk and coordination | Track lifecycle issues, link evidence to reviewed MOSP/MONARC scenarios and use the national overview for permitted organizations. [Risk scenarios](../user-guide/risk-scenarios.md) · [National overview](../user-guide/circl-overview.md) |

## Quick introduction

1. Start at **Infrastructure overview** and choose an organization. Use the software coverage ledger to check what the system knows about each installation.
2. Open **What needs attention?** and choose a machine. In **Vulnerability review**, switch between **By CVE**, **By machine** and **By software**.
3. Open **View software & evidence**. Check the installed version, vendor rule and any listed fix. Verify the update channel or reviewed mitigation on the machine.
4. Use **Notify about this CVE** or the machine action to prepare a FlowIntel plan. Review the action items and recipients before approval.
5. After remediation, check the next applied inventory report and the current version evidence. [Guided walkthrough](../user-guide/guided-cases.md)

## How to try it locally

Use Python 3.12+ and uv. After the tag is published, clone it into a fresh directory. For release review, use the candidate checkout.

```sh
git clone --branch v0.1.0-rc.1 --depth 1 https://github.com/rommelfs/bearings.git
cd bearings
uv sync --frozen
export DJANGO_DEBUG=1
uv run --frozen python manage.py migrate
uv run --frozen python manage.py seed_demo
uv run --frozen python manage.py runserver 127.0.0.1:8000
```

Choose a demo password of at least 12 characters. Open `http://127.0.0.1:8000` and sign in as `company-admin` or `circl-analyst`. Use development settings on loopback. The bundled Docker lab also supports scoped NetBox and optional integrations. [Development lab](../operations/development-stack.md)

## Install or update a server

For Ubuntu 24.04, follow the reviewed upgrade procedure. It covers backups, the pinned checkout, frozen production dependencies, migrations, static collection, package publishing and service checks. Use the server's **Inventory clients** pages to download the Linux or Windows client. Obtain a bounded rollout key from the organization administrator, enroll one test machine and check for the first applied report before expanding the rollout. [Ubuntu installation and upgrade](../operations/ubuntu24.md) · [Linux installation](../integrations/linux-rollout.md) · [Windows installation](../../clients/windows/README.md)

## Validation and coverage

Bearings is a development and pilot workspace. A supported version match establishes the vendor's version condition. Review host configuration and exposure separately. Vendor-listed fixes and repository availability are separate. Windows Update reports read-only cache evidence.
