# MISP restricted cache and CIRCL research pilot

Status: **implemented bounded read/cache pilot; misppriv.circl.lu has not been authenticated or validated live**. The operator-supplied proposed URL is `https://misppriv.circl.lu`; every source URL is configurable. Sources start disabled, have isolated server-side credential references and are never created/enabled automatically on bootstrap. No real key was provided or used during implementation. Normal company users cannot configure or read this cache.

## Configure the bundled lab

```sh
git pull
python3 scripts/dev.py up --no-build
python3 scripts/dev.py configure-misp --url https://misppriv.circl.lu
```

The last command prompts for a hidden read API key; optionally use `--token-file /private/path` for a private single-line file. It creates/updates a **disabled** source, writes an isolated `MISP_CIRCL_TOKEN` file to the private Docker secrets volume with mode 0600 and app ownership, and restarts web/worker to load the reference. It does not contact MISP or enable reads. `--name`, `--credential-ref`, `--actor` and explicit `--allow-private` are configurable; each source has a unique `MISP_*TOKEN` reference. No key is put in process arguments, source records, logs or Git. Reconfiguration disables access and invalidates reader attestations before credential replacement. A source with cached events cannot change URL/reference; create a separate source instead.

As platform-admin, open **National overview → MISP intelligence → Configure MISP sources**. Review URL, refresh interval (default 60 minutes), maximum cache age (default 120 minutes), destination and API-account scope; then explicitly enable the source. The worker checks due sources, one per pass. Or request a complete read manually:

```sh
python3 scripts/dev.py manage sync_misp --source 1
```

For an independently deployed Bearings service, inject the key through its private runtime environment/secret manager and configure the source in platform administration. The bundled secret installer refuses external stack mode. API permission and deployed-version acceptance must be performed using an approved read-only account; a sync-user key is not required. Proxy-DNS installations must explicitly allow the configured MISP hostname in `CONNECTOR_ALLOWED_HOSTS` and retain approved TLS/egress settings. Internal/private destinations require explicit operator approval.

## Read and cache contract

The pinned [MISP 2.5 OpenAPI source](https://github.com/MISP/MISP/blob/7dce1ef58bc16f0249ea4b53b2a29585645145a3/app/webroot/doc/openapi.yaml) documents `Authorization: <API-key>` and `POST /events/restSearch`. This POST is a **read-only search**, not an event push or publication. The pilot requests JSON pages of ten complete events with `metadata=false`, `withAttachments=false`, `excludeLocalTags=false`, `deleted=false`. It accepts the documented `response: [{Event: ...}]` envelope; malformed/duplicate pages, unsupported metadata or exhausted bounds refuse the entire refresh. No upstream pagination links, event-supplied URLs or automatic retries are followed. A source is limited to 500 events/20 MB total, 2 MB per HTTP response, ten-second socket timeouts and a 30-second read budget checked during streaming and between pages. A blocked read can extend the budget by one socket wait; this is not a hard real-time guarantee. Use a dedicated scoped read account/dataset for the pilot. Oversized corpora fail visibly rather than importing a successful-looking partial result.

A short source lease hides cached events while background I/O runs. Network work does not hold a database transaction. One atomic local merge publishes the complete validated response set, source-bound UUID/remote ID, timestamp, canonical content hash and unmodified nested event evidence/markings. Regressing IDs/timestamps refuse the merge. Duplicate data reuses the same local event; policy-only changes also change the digest. Unseen events remain stored but unavailable; reappearance requires renewed analyst approval. Failed/auth/partial imports preserve previous data but **suspend research access**, rather than equating missing results with deletion or safety. Expired worker leases can be retried; active leases prevent duplicate workers. Failed reads retry after five minutes rather than waiting the normal longer refresh interval. Credential/source policy changes rotate the publication generation so an older worker cannot publish even after re-enablement. Source disablement/configuration changes are rechecked before publication.

This cache is not a native MISP replica. Paginated live searches are not guaranteed to be an atomic upstream snapshot. Incremental timestamp/delta/checkpoint replication and periodic authorized-ID manifests are future work; timestamps alone cannot identify newly revoked events. See [the staged operational/product review](../product/next-priorities.md). A dedicated MISP replica can later own native replication if needed; it does not replace recipient-policy checks in Bearings.

## Recipient handling and local research

Only platform administrators initially see fresh complete cached events. A platform administrator inspects the event and **all nested restrictions**, then records named authorized CIRCL analysts, a handling justification and an explicit attestation for that exact digest. A form opened before a content/policy change cannot approve the newer revision. No source-wide role grant implies TLP:RED authorization. A named user must still be an active CIRCL analyst. Content/policy changes invalidate the attestation; source disablement, in-flight reconciliation, failures, missing events and maximum-age expiry hide the cache. Revoked event readers lose access immediately. No cached evidence, title, count or match is added to participant dashboards, national aggregates or notifications.

**National overview → MISP intelligence** lists authorized fresh revisions. Open an event and choose **Research current verified IP / domain assignments**. This is a CSRF-protected local POST, not a MISP inventory upload. It checks at most 100 attributes (including bounded object attributes), 2,000 currently visible verified claims and 100 output leads; reached bounds are explicit. Supported values are domain/hostname, public individual IP source/destination and domain|IP. DNS label boundaries and proper address arithmetic apply; private IPs, unverified claims and unsupported indicator types are excluded. Results link to the company's scoped contact section and explain the current assignment. Event modification time is not treated as observation time; historical victim attribution and software/version matching are not yet implemented.

A creator organization UUID or indicator match does not identify a victim or prove compromise. Determine victim/malicious/contextual roles from original evidence. Research creates no finding, risk score, notification or upstream sighting. An existing MISP organization reference remains operator-attested correlation metadata. A reviewed, recipient-safe outreach draft is a separate next increment. Data in the source event is escaped plain JSON; display is capped and the original-event link is constructed from the configured source and validated UUID. Raw search criteria/event contents are not written to audit logs.

Cached payloads are sensitive database content. Protect database, volumes and backups with the deployment's access/encryption/retention controls; this pilot does not implement automatic retention deletion or database encryption. Live service/version/key capability, full redistribution rules, large-corpus replication and operational retention/recovery are not claimed validated. Production notifications, MISP writes/publication, user creation and native SSO configuration remain off. See [ecosystem account/integration design](ecosystem-accounts.md).
