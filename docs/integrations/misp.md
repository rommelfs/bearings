# MISP restricted cache and CIRCL research pilot

Status: **implemented bounded read/cache pilot; misppriv.circl.lu has not been authenticated or validated live**. The operator-supplied proposed URL is `https://misppriv.circl.lu`; every source URL is configurable. Sources start disabled, have isolated server-side credential references and are never created/enabled automatically on bootstrap. No real key was provided or used during implementation. Normal company users cannot configure or read this cache.

## Configure the bundled lab

```sh
git pull
python3 scripts/dev.py up --no-build
python3 scripts/dev.py configure-misp --owner circl-analyst --misp-user-id 123 --url https://misppriv.circl.lu
```

Use an individual Bearings account (not a shared demonstration login), the selected analyst’s own read-only key and their native MISP user ID (replace `123` with that account’s ID). Never supply your personal key for another analyst. The last command prompts for a hidden read API key; optionally use `--token-file /private/path` for a private single-line file. It creates/updates a **disabled** source, writes an isolated per-owner `MISP_USER_<hash>_TOKEN` file to the private Docker secrets volume with mode 0600 and app ownership, and restarts web/worker to load the reference. It does not contact MISP or enable reads. `--name`, `--credential-ref`, `--actor` and explicit `--allow-private` are configurable; each source has a unique `MISP_*TOKEN` reference. No key is put in process arguments, source records, logs or Git. Reconfiguration disables cache access and invalidates an in-flight publication before credential replacement. A source with cached events cannot change URL/reference; create a separate source instead.

As platform-admin, open **National overview → MISP intelligence → Configure MISP sources**. Review URL, refresh interval (default 5 minutes), maximum cache age (default 10 minutes; configurable up to 60), destination and API-account scope; then explicitly enable the source. The worker checks due sources, one per pass. Or request a complete read manually:

```sh
python3 scripts/dev.py manage sync_misp --source 1
```

For an independently deployed Bearings service, inject the key through its private runtime environment/secret manager and configure the source in platform administration. The bundled secret installer refuses external stack mode. Every enabled source must bind one active Bearings analyst/platform user to one operator-confirmed native MISP user ID and a separate personal key. Before every snapshot, `GET /users/view/me` must match the pinned ID; the potentially secret-bearing user response is never retained/logged. A wrong identity aborts before event search. A read-only key suffices; restricted endpoint allowlists must permit this self-read and the event search. API permission and deployed-version acceptance must be performed using that personal read-only account; a sync-user key is not required. Proxy-DNS installations must explicitly allow the configured MISP hostname in `CONNECTOR_ALLOWED_HOSTS` and retain approved TLS/egress settings. Internal/private destinations require explicit operator approval.

## Read and cache contract

The pinned [MISP 2.5 OpenAPI source](https://github.com/MISP/MISP/blob/7dce1ef58bc16f0249ea4b53b2a29585645145a3/app/webroot/doc/openapi.yaml) documents `Authorization: <API-key>` and `POST /events/restSearch`. This POST is a **read-only search**, not an event push or publication. The pilot requests JSON pages of ten complete events with `metadata=false`, `withAttachments=false`, `excludeLocalTags=false`, `deleted=false`. It accepts the documented `response: [{Event: ...}]` envelope; malformed/duplicate pages, unsupported metadata or exhausted bounds refuse the entire refresh. No upstream pagination links, event-supplied URLs or automatic retries are followed. A source is limited to 500 events/20 MB total, 2 MB per HTTP response, ten-second socket timeouts and a 30-second read budget checked during streaming and between pages. A blocked read can extend the budget by one socket wait; this is not a hard real-time guarantee. Use a dedicated scoped read account/dataset for the pilot. Oversized corpora fail visibly rather than importing a successful-looking partial result.

A short source lease hides cached events while background I/O runs. Network work does not hold a database transaction. One atomic local merge publishes the complete validated response set, source-bound UUID/remote ID, timestamp, canonical content hash and unmodified nested event evidence/markings. Regressing IDs/timestamps refuse the merge. Duplicate data reuses the same local event; policy-only changes also change the digest. Unseen events remain stored but unavailable; reappearance requires renewed analyst approval. Failed/auth/partial imports preserve previous data but **suspend research access**, rather than equating missing results with deletion or safety. Expired worker leases can be retried; active leases prevent duplicate workers. Failed reads retry after five minutes rather than waiting the normal longer refresh interval. Credential/source policy changes rotate the publication generation so an older worker cannot publish even after re-enablement. Source disablement, ownership/native-ID/configuration changes and current owner eligibility are rechecked before publication.

This cache is not a native MISP replica. Paginated live searches are not guaranteed to be an atomic upstream snapshot. Incremental timestamp/delta/checkpoint replication and periodic authorized-ID manifests are future work; timestamps alone cannot identify newly revoked events. See [the staged operational/product review](../product/next-priorities.md). A dedicated MISP replica can later own native replication if needed; it does not replace recipient-policy checks in Bearings.

## Recipient handling and local research

Only the active source owner can read its cache, including titles/counts and local research. A platform administrator can manage source metadata but has no global event-reading bypass. Source credentials and caches are isolated even for the same event UUID. There is no Bearings event-reader grant; prior grant metadata is retained for history but never authorizes access. Ownership/native-ID/URL/reference cannot be repointed after cached events exist. Owner deactivation/analyst-role removal, source disablement, failures, in-flight refresh and cache expiry hide the data.

Migration 0039 quarantines all previous shared-key sources and their cached events without transferring ownership or deleting raw history. Configure new personal connections after restarting all web/worker replicas; do not enable them while legacy code is still serving. A complete successful refresh under the pinned personal identity is required before access. MISP permissions are checked at refresh time, so upstream revocation has a bounded lag until the next refresh/expiry; this is not instantaneous per-request upstream authorization. Defaults are five-minute refresh and ten-minute maximum cache age, configurable within a sixty-minute upper bound. Page navigation remains local and never renews stale permissions implicitly.

Company members need no MISP key and cannot read these events. An authorized analyst must separately review any recipient-safe notification; owning a readable MISP cache grants no permission to redistribute its content or derived information to a company. Distribution/sharing restrictions are enforced by the personal MISP API response, while TLP handling and external release decisions remain independent. This replaces the initial pilot’s manual event-recipient grant approach.
**National overview → MISP intelligence** lists authorized fresh revisions. Open an event and choose **Research current verified IP / domain assignments**. This is a CSRF-protected local POST, not a MISP inventory upload. It checks at most 100 attributes (including bounded object attributes), 2,000 currently visible verified claims and 100 output leads; reached bounds are explicit. Supported values are domain/hostname, public individual IP source/destination and domain|IP. DNS label boundaries and proper address arithmetic apply; private IPs, unverified claims and unsupported indicator types are excluded. Results link to the company's scoped contact section and explain the current assignment. Event modification time is not treated as observation time; historical victim attribution and software/version matching are not yet implemented.

A creator organization UUID or indicator match does not identify a victim or prove compromise. Determine victim/malicious/contextual roles from original evidence. Research creates no finding, risk score, notification or upstream sighting. An existing MISP organization reference remains operator-attested company correlation metadata, separate from personal MISP user identity. A reviewed, recipient-safe outreach draft is a separate next increment. Data in the source event is escaped plain JSON; display is capped and the original-event link is constructed from the configured source and validated UUID. Raw search criteria/event contents are not written to audit logs.

Cached payloads are sensitive database content. Protect database, volumes and backups with the deployment's access/encryption/retention controls; this pilot does not implement automatic retention deletion or database encryption. Live service/version/key capability, full redistribution rules, large-corpus replication and operational retention/recovery are not claimed validated. Production notifications, MISP writes/publication, user creation and native SSO configuration remain off. See [ecosystem account/integration design](ecosystem-accounts.md).
