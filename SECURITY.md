# Security reporting

Do not post vulnerabilities, credentials, organization inventories, contacts, or restricted intelligence in public issues.

A project-specific reporting address and encryption key have **not yet been verified**. No address or key is invented here. Until the owner establishes the reporting channel, use GitHub private vulnerability reporting if it is enabled for this repository, or ask the repository owner privately for a secure channel without including sensitive details. Confirm the destination and key through an independently trusted channel before sending evidence.

This is development software, not an approved production service. Production readiness requires security review, deployment hardening, operational ownership, recovery exercises, identity controls, and notification authorization; see the backlog. Organization isolation tests cover the implemented slice, not all planned integrations.
