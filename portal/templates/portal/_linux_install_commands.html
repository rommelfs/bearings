1. Download and install on your Linux server

Run this complete block in a terminal on the machine you want to monitor. Python 3.8+, curl, systemd and sudo are required. Paste your rollout key at the hidden prompt.

curl --fail --show-error --proto '=https' '{{ origin }}/downloads/linux/install.py' -o bearings-install.py &&
sudo python3 bearings-install.py --server '{{ origin }}' --bootstrap-prompt

Installing inside a constrained LXC container

Use this complete block instead:

curl --fail --show-error --proto '=https' '{{ origin }}/downloads/linux/install.py' -o bearings-install.py &&
sudo python3 bearings-install.py --server '{{ origin }}' --bootstrap-prompt --lxc-compatible

2. Check that reporting has started

sudo systemctl --no-pager --full status bearings-linux.service

After successful registration, periodic reporting starts automatically. Check the device under your company’s Linux / Windows inventory reports.

Automated rollout with a secret manager

Run as root. First have your secret manager provision a root-readable file at /run/secrets/bearings-rollout-key (permissions 0600). This path is an example: adapt it to your deployment. The following block downloads the installer, then reads the key from that file through standard input:

curl --fail --show-error --proto '=https' '{{ origin }}/downloads/linux/install.py' -o bearings-install.py &&
python3 bearings-install.py --server '{{ origin }}' --bootstrap-stdin < /run/secrets/bearings-rollout-key

Add --lxc-compatible for constrained LXC. Keep the key out of command arguments, logs and reusable images. Each machine generates its own device identity.

3. Automatic client updates

Automatic client updates are enabled by default. At a terminal, press Enter for yes or answer no; unattended installs enable updates without reading an extra stdin answer. Use --no-auto-update to opt out, or --auto-update to accept without prompting.

For older installations without an updater, enable it once as an administrator. New HTTPS installations configure it automatically and wait for enrollment if needed. The client checks this trusted HTTPS server daily with a randomized delay of up to four hours. Unchanged releases download only checksums and do not restart reporting. Keys, profiles, pending reports and local service drop-ins are retained.

sudo python3 bearings-install.py auto-update-enable --server '{{ origin }}'

The installed updater stays local; it never downloads and executes a replacement installer. Failed replacements restore the previous client and quarantine that publication. Server operators still publish reviewed client releases explicitly.

Update status, immediate check and disabling 
sudo python3 /usr/local/lib/bearings-linux/update.py auto-update-status
sudo systemctl start bearings-linux-update.service
sudo journalctl -u bearings-linux-update.service --no-pager -n 40
sudo python3 /usr/local/lib/bearings-linux/update.py auto-update-disable

Disabling updates keeps ordinary inventory reporting running. A startup check confirms service activity, not successful report delivery or complete application health.
