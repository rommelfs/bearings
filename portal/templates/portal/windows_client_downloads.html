Install and enroll

  1. Extract the ZIP from this Bearings server and double-click bearings-windows.exe under the Windows account that will send reports. The setup window displays the preconfigured HTTPS server.
  2. In Linux / Windows inventory reports, a company administrator selects the existing asset and chooses Create a Windows registration code. Paste the one-time code into the setup window and choose Enroll and send first report.
  3. Choose Check status until the report shows applied. Choose Enable automatic reports and confirm. The client copies itself to %LOCALAPPDATA%\Programs\Bearings and registers a task for the same account.

Windows verifies HTTPS with its certificate store. For servers using a private CA, your IT administrator can distribute the approved trust certificate through Windows.

PowerShell setup and reporting commands 
.\bearings-windows.exe --version
.\bearings-windows.exe enroll --code
.\bearings-windows.exe report
.\bearings-windows.exe status

Rollout to several computers

Pilot one existing asset first. Use your organization’s software distribution tool to copy the approved EXE to the other computers. Create a separate code for each existing asset, redeem it under its reporting account, and verify the first report before enabling its schedule.

Keep registration codes out of rollout scripts, command lines and logs. Keep device state local to its original account and device. This enrollment process supports existing assets and a separate approval for each device.

Start periodically

The setup window creates a task named Bearings Windows Inventory followed by an account-specific suffix. It runs every six hours while that account is signed in. Pause any earlier Bearings task before switching to the new one. Use Task Scheduler to confirm the first run.

Foreground reporting and manual Task Scheduler setup

For a foreground run, use watch. It reports at startup and every six hours while the process is open.

.\bearings-windows.exe watch --interval 21600

For daily operation, create a task in Windows Task Scheduler:

  1. Choose Create Task and select the same Windows account and profile used for enrollment. For a pilot, choose Run only when user is logged on and leave elevation off.
  2. Set a daily trigger that repeats every six hours for one day. Enable running after a missed start and choose Do not start a new instance for overlaps.
  3. Use the absolute path to bearings-windows.exe as Program/script and report as Add arguments. If enrollment used a custom --state-dir, append the same absolute directory in quotes.
  4. Run the task manually. Under the reporting account, confirm that status shows the new report as applied. For signed-out operation, validate the task with that account’s profile and DPAPI access before rolling it out.

Update an enrolled client

  1. Download and verify the new ZIP for the same architecture and extract it into a staging folder. Run the staged EXE with --version.
  2. Pause the task and let any active report finish. Stop any foreground watch. Keep a copy of the old EXE, then replace it in the existing program directory.
  3. Keep the reporting account, profile and state directory. The default state is %LOCALAPPDATA%\Bearings\Windows. Updating the executable preserves the enrollment and queued reports, including state from the Python reference client. Device credentials expire after 90 days. Ask your administrator to review expired credentials.
  4. Run report and status with the replacement and confirm the new report was applied. Re-enable the schedule and run it once. For binary rollback, use the prior compatible EXE with the current state directory.
