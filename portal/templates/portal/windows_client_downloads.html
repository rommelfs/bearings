Install and enroll

  1. Extract the ZIP from this Bearings server and double-click bearings-windows.exe under the Windows account that will send reports. The setup window displays the preconfigured HTTPS server.
  2. Paste the shared Bearings rollout key. Choose Register and enable reports. The client registers the computer as a new host, sends the first report and creates the scheduled task for your signed-in account.

Windows verifies HTTPS with its certificate store. For servers using a private CA, your IT administrator can distribute the approved trust certificate through Windows.

PowerShell setup and reporting commands 
.\bearings-windows.exe --version
.\bearings-windows.exe enroll --code
.\bearings-windows.exe report
.\bearings-windows.exe status

Rollout to several computers

Pilot one Windows host first. Use your organization’s software distribution tool to copy the approved EXE to the other computers. Use the authorized rollout key on each computer under its reporting account. Verify the enrolled hosts and receipts in the organization’s inventory reports.

Keep registration codes out of rollout scripts, command lines and logs. Keep device state local to its original account and device. The rollout key controls the organization, host type, inventory mode, maximum devices and expiry.

Start periodically

The setup window creates a task named Bearings Windows Inventory followed by an account-specific suffix. It runs every six hours while that account is signed in. Choose Check status to see whether the task was verified and whether the latest report was applied. If the task could not be created, choose Enable automatic reports to retry. Use Task Scheduler to confirm the first run.

Foreground reporting and manual Task Scheduler setup

For a foreground run, use watch. It reports at startup and every six hours while the process is open.

.\bearings-windows.exe watch --interval 21600

For daily operation, create a task in Windows Task Scheduler:

  1. Choose Create Task and select the same Windows account and profile used for enrollment. For a pilot, choose Run only when user is logged on and leave elevation off.
  2. Set a daily trigger that repeats every six hours for one day. Enable running after a missed start and choose Do not start a new instance for overlaps.
  3. Use the absolute path to bearings-windows.exe as Program/script and report as Add arguments. If enrollment used a custom --state-dir, append the same absolute directory in quotes.
  4. Run the task manually. Under the reporting account, confirm that status shows the new report as applied. For signed-out operation, validate the task with that account’s profile and DPAPI access before rolling it out.

Automatic client updates

New publisher builds automatically check for signed Bearings client releases after report attempts. The normal six-hour task activates a new verified version when available. Its existing entry path starts that version. The next run uses that version; registration and pending reports stay intact. This updates Bearings, not Windows or other applications.

Use update --auto-update=status for local update status, update to check now, or update --auto-update=disable / enable to change the local preference. Report status and client update status are separate.

Existing older clients need one manual bootstrap upgrade:

  1. Download and verify the new ZIP for the same architecture and extract it into a staging folder. Run the staged EXE with --version.
  2. Pause the task and let any active report finish. Stop any foreground watch. Keep a copy of the old EXE, then replace it in %LOCALAPPDATA%\Programs\Bearings. If setup previously copied the EXE but failed to create the task, update that copy and choose Enable automatic reports.
  3. Keep the reporting account, profile and state directory. The default state is %LOCALAPPDATA%\Bearings\Windows. Updating the executable preserves the enrollment and queued reports, including state from the Python reference client. Device credentials expire after 90 days. Ask your administrator to review expired credentials.
  4. Run report and status with the replacement and confirm the new report was applied. Re-enable the schedule and run it once. For later automatic updates, preserve the publisher signing key on the server. Investigate update errors separately; never delete enrollment state to retry.
